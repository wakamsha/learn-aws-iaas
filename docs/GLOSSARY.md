## AWS 全般とアカウント

| 用語 | 意味 | 初出 |
| --- | --- | --- |
| リージョン(Region) | AWS のデータセンター群がある地理的な単位。このカリキュラムでは `ap-northeast-1`(東京)を使う | 0 |
| グローバルサービス | リージョンに属さないサービス。CloudFront や IAM が該当する | 1 |
| AZ(Availability Zone) | 1 つのリージョン内にある、電源・ネットワークが独立したデータセンター群。冗長化の単位になる | 2 |
| ARN(Amazon Resource Name) | AWS のリソースを一意に指す識別子。`arn:aws:s3:::bucket-name` のような形をとる | 1 |
| Management Console | AWS をブラウザから操作する GUI。このカリキュラムでは観察とデバッグに使う | 0 |
| AWS CLI | AWS の API をコマンドラインから呼ぶツール。`describe-*` / `list-*` / `get-*` は読み取り専用 | 0 |
| ルートユーザー | アカウント作成時のメールアドレスでログインする、全権限を持つ主体。日常の作業には使わない | 0 |
| MFA | 多要素認証。パスワードに加えて、認証アプリなどの 2 つ目の要素を求める | 0 |
| IAM Identity Center | 人間のユーザーに AWS アカウントへのアクセスを与えるサービス。SSO でログインし、一時クレデンシャルを受け取る。旧称 AWS SSO | 0 |
| 許可セット(Permission Set) | IAM Identity Center で、ユーザーにどの権限を与えるかの定義。割り当てるとアカウント内にロールが作られる | 0 |
| CLI プロファイル | AWS CLI の接続設定(アカウント、ロール、リージョン)の名前付きの組。`AWS_PROFILE` で選ぶ | 0 |
| 一時クレデンシャル | 有効期限付きのアクセスキー。期限が切れると使えなくなるので、漏れたときの被害が限られる | 0 |
| 長期アクセスキー | IAM ユーザーに発行する、期限のないアクセスキー。漏れると無効化するまで使われ続ける | 0 |
| CloudTrail | AWS の API 呼び出しを記録するサービス。「イベント履歴」で管理イベント(作成・変更・削除)をさかのぼれる | 0 |
| 管理イベント | CloudTrail が記録する、リソースの作成・変更・削除などの操作。`requestParameters` に API の引数が残る | 0 |
| AWS Budgets | 予算を決め、実績や予測が超えたら通知するサービス | 0 |
| Cost Anomaly Detection | いつもと違う費用の増え方を検知して通知するサービス | 0 |
| コスト配分タグ | 請求画面で費用を分けて見るために有効化したタグ | 0 |
| 無料利用枠(Free Tier) | 一定量まで料金がかからない枠。条件は時期とアカウントによって変わる | 0 |
| 時間課金 | 使っていなくても、存在しているだけで時間単位で料金がかかる性質 | 0 |
| タグ | リソースに付けるキーと値の組。検索・費用の集計・後片付けに使う | 0 |
| 結果整合性(Eventual Consistency) | 変更がすべての場所に反映されるまでに時間差があること。作成直後に一覧に出ない、作ったロールがすぐ使えない、などの形で現れる | 1 |

## Terraform

| 用語 | 意味 | 初出 |
| --- | --- | --- |
| IaC(Infrastructure as Code) | インフラの構成をコードで書き、そのコードから作成・変更・削除する手法 | 0 |
| HCL | Terraform の設定を書く言語。`.tf` ファイルの中身 | 0 |
| provider | Terraform が特定のサービス(AWS など)の API を呼ぶためのプラグイン。リソースの種類と引数は provider が定義する | 0 |
| Terraform Registry | provider と module の公開場所。各リソースの引数と属性のリファレンスがある | 0 |
| resource | Terraform が作成・管理するもの 1 つ。`resource "aws_s3_bucket" "this" { ... }` の形で書く | 0 |
| 引数と属性 | 引数はリソースに自分が書く入力値。属性はリソースから読める値で、作成後に AWS が決める値(ID、ARN など)も含む | 0 |
| リソースアドレス | state の中でリソースを指す名前。`aws_s3_bucket.this` のような形 | 0 |
| `terraform init` | provider のダウンロードなど、作業ディレクトリの準備をするコマンド | 0 |
| `terraform plan` | コードと state と実際のリソースを比べ、apply したら何が起きるかを表示するコマンド | 0 |
| `terraform apply` | plan の内容を実際に実行するコマンド | 0 |
| `terraform destroy` | state にあるリソースをすべて削除するコマンド | 0 |
| `terraform fmt` / `validate` | `fmt` はコードの整形、`validate` は構文と参照の整合の確認。どちらも AWS に問い合わせない | 0 |
| `.terraform/` | `init` がダウンロードした provider などを置くディレクトリ。commit しない | 0 |
| `.terraform.lock.hcl` | 使う provider のバージョンとハッシュを固定するファイル。commit する | 0 |
| `required_version` / バージョン制約 | `versions.tf` に書く、Terraform 本体と provider の許容バージョンの範囲 | 0 |
| state | Terraform が「どのリソースを自分が管理しているか」と、その属性を記録したもの。既定では `terraform.tfstate` というファイル。秘密情報が平文で入り得る | 0 |
| ローカル state | state を手元のファイルに置く方式。Phase 0〜3 はこれを使う | 0 |
| drift | Console などで手で変更され、実際のリソースがコードや state と食い違った状態 | 0 |
| plan の記号 | `+` 作成、`~` in-place 更新、`-/+` replace(削除して作り直し)、`-` 削除 | 0 |
| in-place 更新 | リソースを残したまま設定だけを変える変更 | 0 |
| replace | リソースを削除して作り直す変更。ID が変わり、中のデータが消えることがある | 0 |
| ForceNew | provider が「この引数を変えたら replace になる」と定義していること。多くは AWS API がその変更を提供していないことに由来する | 0 |
| `import` | Terraform の外で作られた既存のリソースを、state に取り込む操作 | 必要時 |
| `default_tags` | provider ブロックに書く、すべてのリソースに付けるタグ | 0 |
| `tags` / `tags_all` | `tags` はリソースに書いたタグ、`tags_all` は `default_tags` と合わせて実際に付くタグ | 0 |
| ルートモジュール | `terraform` コマンドを実行するディレクトリの `.tf` ファイル群 | 0 |
| data source | 既存のリソースや情報を読み取るだけのブロック。`data "..." "..." { ... }` の形で書く | 1 |
| 文字列補間 | `"prefix-${式}"` の形で、文字列の中に式の値を埋め込む書き方 | 1 |
| 暗黙の参照 | あるリソースの属性を別のリソースの引数に書くこと。Terraform はこれを見て作成順序を決める | 1 |
| 依存グラフ | リソース間の参照から Terraform が組み立てる、作成・削除の順序 | 1 |
| `depends_on` | 参照では表せない依存関係を明示的に書く引数 | 1 |
| `aws_iam_policy_document` | IAM ポリシーの JSON を HCL で組み立てる data source | 1 |
| provider エイリアス | 同じ provider を設定違い(別リージョンなど)で複数使うための別名 | 1 |
| `variable` | ルートモジュールや module の入力値 | 2 |
| `locals` | モジュール内で使い回す値に名前を付けるブロック | 2 |
| `output` | モジュールから外に出す値。ルートモジュールの output は `terraform output` で読める | 0 |
| `*.tfvars` | `variable` に渡す値を書くファイル | 2 |
| `count` | 同じリソースを番号付きで複数作る引数。要素は `[0]`, `[1]` のように番号で識別される | 2 |
| `for_each` | 同じリソースを、マップや集合のキーごとに複数作る引数。要素はキーで識別される | 2 |
| 組み込み関数 | Terraform に用意された関数。`cidrsubnet`(CIDR の分割)、`jsonencode`(値を JSON 文字列に変換)など | 2 |
| module | `.tf` ファイル群を入力(`variable`)と出力(`output`)を持つ部品にしたもの | 3 |
| リモート state / backend | state を S3 などの共有の場所に置く方式と、その置き場所の設定 | 4 |
| state のロック | 複数人・複数プロセスが同時に apply して state を壊さないための排他制御 | 4 |
| bootstrap | state を置くバケットのように、Terraform の前提になるものを最初に用意する作業 | 4 |
| Terraform workspaces | 1 つの設定から複数の state を切り替えて使う機能 | 4 |
| `tflint` | Terraform のコードの静的解析ツール。`validate` では見つからない誤りや慣習違反を指摘する | 4 |
| mise / tfenv | Terraform のバージョンをディレクトリごとに切り替えるツール | 0 |

## IAM

| 用語 | 意味 | 初出 |
| --- | --- | --- |
| IAM | AWS の「誰が、何に、何をできるか」を管理するサービス | 0 |
| 主体(Principal) | AWS の API を呼ぶ側。IAM ユーザー、ロール、AWS サービスなど | 1 |
| IAM ユーザー | 長期のクレデンシャルを持つ主体 | 1 |
| IAM ロール | 引き受けた主体に一時クレデンシャルを渡す主体。人間にも AWS サービスにも引き受けさせられる | 2 |
| ポリシー | 許可・拒否を JSON で書いた文書。`Effect` / `Action` / `Resource` / `Condition` で構成される | 1 |
| アイデンティティベースのポリシー | 主体(ユーザー・ロール)の側に付けるポリシー。「この主体は何をできるか」 | 1 |
| リソースベースのポリシー | リソース(S3 バケットなど)の側に付けるポリシー。「このリソースに誰が何をできるか」。バケットポリシーが代表例 | 1 |
| 権限ポリシー | ロールが引き受けられた後に何をできるかを定めるポリシー | 2 |
| 信頼ポリシー | 誰がそのロールを引き受けられるかを定めるポリシー。ロールに付く | 2 |
| 明示的 Deny / 暗黙の Deny | ポリシーに `Deny` と書かれている状態と、どのポリシーにも `Allow` がない状態。どちらも拒否になり、明示的 Deny は Allow より優先される | 1 |
| 最小権限 | 必要な操作と対象だけを許可すること | 1 |
| STS | 一時クレデンシャルを発行するサービス | 0 |
| AssumeRole | ロールを引き受けて、そのロールの一時クレデンシャルを受け取る STS の API | 2 |
| インスタンスプロファイル | EC2 インスタンスにロールを渡すための入れ物 | 2 |
| OIDC(OpenID Connect) | 外部の ID 発行者が発行したトークンで身元を証明する仕組み。GitHub Actions は長期アクセスキーなしでこれを使ってロールを引き受けられる | 4 |
| OIDC プロバイダー | AWS が信頼する外部の ID 発行者(GitHub など)を IAM に登録したもの | 4 |

## ネットワーク

| 用語 | 意味 | 初出 |
| --- | --- | --- |
| IP アドレス | ネットワーク上の機器の住所。IPv4 は `10.0.1.25` のような 32 ビットの値 | 2 |
| CIDR | IP アドレスの範囲を `10.0.0.0/16` のように表す記法。`/` の後の数字が大きいほど範囲は狭い | 2 |
| `0.0.0.0/0` | すべての IPv4 アドレス。ルートでは「それ以外すべての宛先」、SG では「インターネット全体」を意味する | 2 |
| VPC | AWS 上に作る、自分専用の論理的なネットワーク | 2 |
| サブネット | VPC の CIDR を分割した範囲。1 つの AZ に属する | 2 |
| public subnet / private subnet | インターネットと直接やり取りできるサブネットと、できないサブネット。サブネット自体にこの設定はなく、関連付けたルートテーブルで決まる | 2 |
| ルートテーブル | 宛先ごとに、パケットを次にどこへ送るかを決める表。サブネットに関連付ける | 2 |
| Internet Gateway(IGW) | VPC とインターネットをつなぐ出入口 | 2 |
| NAT Gateway | private subnet から外へ出る通信を、自分のパブリック IP に置き換えて中継するもの。外から内への通信は通さない。時間課金 | 2 |
| パブリック IPv4 アドレス | インターネットから到達できる IPv4 アドレス。時間課金 | 2 |
| Elastic IP | 固定のパブリック IPv4 アドレス。リソースに付け替えられる | 2 |
| ENI(Elastic Network Interface) | VPC 内の仮想的なネットワークカード。プライベート IP と SG はこれに付く | 2 |
| Security Group(SG) | ENI 単位のファイアウォール。許可ルールだけを書く。ステートフル | 2 |
| SG の参照 | SG のルールの相手に、CIDR の代わりに別の SG を指定すること。「その SG を持つ相手からの通信」を許可する | 2 |
| Network ACL(NACL) | サブネット単位のファイアウォール。許可と拒否の両方を番号順に評価する。ステートレス | 2 |
| ステートフル / ステートレス | 行きの通信を許可したら戻りも自動で許可されるのがステートフル。戻りにも別途ルールが要るのがステートレス | 2 |
| 通信マトリクス | どこから、どこへ、どのポートの通信を許可・拒否するかをまとめた表 | 2 |
| タイムアウト / connection refused | パケットが途中で捨てられて応答がない状態と、相手まで届いたがそのポートで待ち受けていない状態。どこで止まっているかの手がかりになる | 2 |
| VPC エンドポイント | インターネットを経由せずに、VPC から AWS のサービスへ接続する経路。Gateway 型と、ENI を作る Interface 型(時間課金)がある | 3 |
| DNS | ドメイン名を IP アドレスに変換する仕組み | 1 |
| TLS | 通信を暗号化し、相手が本物かを証明書で確かめるプロトコル。HTTPS の S | 1 |
| ACM(AWS Certificate Manager) | TLS 証明書を発行・管理するサービス。CloudFront で使う証明書は `us-east-1` に置く | 1 |

## コンピュート(EC2)

| 用語 | 意味 | 初出 |
| --- | --- | --- |
| EC2 | AWS の仮想マシン(インスタンス)のサービス | 2 |
| AMI | インスタンスの起動元になる OS イメージ | 2 |
| インスタンスタイプ | インスタンスの CPU・メモリの組み合わせ。`t3.micro` など | 2 |
| EBS | インスタンスに付けるディスク(ブロックストレージ)。インスタンスを停止しても残り、課金も続く | 2 |
| user data | インスタンスの初回起動時に実行させるスクリプト。cloud-init が実行する | 2 |
| IMDS(Instance Metadata Service) | インスタンスの中から、自分の ID やロールの一時クレデンシャルを取得できる仕組み | 2 |
| IMDSv2 | IMDS の利用前にトークンの取得を必須にする方式。トークンなしの取得を拒否できる | 2 |
| Session Manager | SSH 鍵や開いたポートなしで、インスタンスにシェルで入れる AWS Systems Manager の機能。手元には Session Manager plugin が要る | 2 |
| ALB(Application Load Balancer) | HTTP / HTTPS のリクエストを複数のターゲットに振り分けるロードバランサー。時間課金 | 2 |
| リスナー | ALB が待ち受けるポートとプロトコル、受けたリクエストをどこへ転送するかの規則 | 2 |
| ターゲットグループ | ALB の転送先の集まり。ヘルスチェックの設定を持つ | 2 |
| ターゲット | ターゲットグループに登録された転送先。インスタンスまたは IP アドレス | 2 |
| ヘルスチェック | ターゲットが正常に応答するかを定期的に確かめる仕組み。異常と判定されたターゲットには転送しない | 2 |
| 502 / 503 / 504 | ALB が自分で返すエラー。どれが返るかで、止まっている場所の見当が付く | 2 |
| Launch Template | インスタンスを起動するときの設定(AMI、インスタンスタイプ、SG、user data など)のひな型 | 2 |
| Auto Scaling Group(ASG) | 指定した台数のインスタンスを保つ仕組み。インスタンスが落ちると補充する | 2 |

## コンテナ(ECR / ECS)

| 用語 | 意味 | 初出 |
| --- | --- | --- |
| コンテナイメージ | アプリと実行環境をまとめたもの。デプロイの単位になる | 3 |
| ECR | コンテナイメージを置くレジストリ | 3 |
| タグとダイジェスト | タグは `v1.2.0` のような人間向けの名前で、付け替えられる。ダイジェストはイメージの中身から計算したハッシュで、中身が同じなら変わらない | 3 |
| イミュータブルなタグ | 一度付けたタグを別のイメージに付け替えられないようにする ECR の設定 | 3 |
| イメージスキャン | イメージに含まれるパッケージの既知の脆弱性を検出する ECR の機能 | 3 |
| ライフサイクルポリシー | 古いイメージなどを規則に従って自動で削除する設定。S3 にも同名の機能がある | 3 |
| ECS | コンテナの起動・停止・配置を管理するサービス | 3 |
| Fargate | サーバーの管理なしでコンテナを動かす、ECS の実行環境 | 3 |
| クラスター | ECS のタスクとサービスをまとめる論理的な単位 | 3 |
| タスク定義 | コンテナの設計図。イメージ、CPU / メモリ、ポート、環境変数、ロールなどを書く。変更するたびに新しいリビジョンになる | 3 |
| タスク | タスク定義から起動された、実行中のコンテナの組 | 3 |
| サービス | 指定した数のタスクを保ち、ALB に登録する仕組み。Phase 2 の ASG に近い役割を担う | 3 |
| タスク実行ロール | ECS がタスクを起動するために使うロール。イメージの取得やログの送信を行う | 3 |
| タスクロール | タスクの中のアプリが AWS の API を呼ぶときに使うロール | 3 |
| `awsvpc` ネットワークモード | タスクごとに ENI を持たせる方式。Fargate ではこれを使う | 3 |
| `target_type = ip` | ターゲットグループにインスタンスではなく IP アドレスを登録する設定 | 3 |
| ローリング更新 | 古いタスクを少しずつ新しいタスクに置き換えるデプロイ方式 | 3 |
| デプロイサーキットブレーカー | 新しいタスクが起動に失敗し続けたらデプロイを止め、前のバージョンに戻す ECS の機能 | 3 |
| ロールバック | 問題のあるデプロイを取り消し、前のバージョンに戻すこと | 3 |
| ECS Exec | 実行中のコンテナにシェルで入る機能。Session Manager の仕組みを使う | 3 |
| `runtime_platform` | タスク定義で、CPU アーキテクチャ(`X86_64` / `ARM64`)と OS を指定する引数 | 3 |
| `awslogs` | コンテナの標準出力を CloudWatch Logs に送るログドライバー | 3 |

## データと秘密

| 用語 | 意味 | 初出 |
| --- | --- | --- |
| S3 | オブジェクト(ファイル)をバケットに保存するストレージサービス | 0 |
| バケット / オブジェクト | バケットは保存先の入れ物で、名前は全世界で一意。オブジェクトはそこに置く 1 つ 1 つのファイル | 0 |
| バージョニング | オブジェクトを上書き・削除しても、以前のバージョンを残す S3 の設定 | 0 |
| パブリックアクセスブロック | バケットポリシーや ACL の設定にかかわらず、公開を禁止する S3 の設定 | 0 |
| バケットポリシー | バケットに付けるリソースベースのポリシー | 1 |
