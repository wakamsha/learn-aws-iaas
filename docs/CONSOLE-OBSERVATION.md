# Console の裏側を観察する

このカリキュラムの先にある目標は、AWS Management Console のような GUI プロダクトの開発で FE specialist として活躍すること。
Terraform でリソースを 1 つずつ書くことは、Console が 1 画面で隠しているものを分解して見ることでもある。

**観察は学習者の判断を増やすためのものではない。** 1 Phase につき 1 回、振り返りの「Console で気づいたこと」に回収する。

## 道具

### CloudTrail のイベント履歴

管理イベント(作成・変更・削除)を、追加設定なしでさかのぼって見られる。

- Console で操作した直後と、apply した直後に、それぞれイベント名とユーザー名で絞り込んで比べる
- イベントの `requestParameters` を読むと、フォームの項目がどの API パラメータになっているかが分かる
- 反映には数分かかることがある

### ブラウザの DevTools

自分のブラウザで開いている Console の Network タブで、ポーリングの間隔、ページング、エラー時のレスポンスが見える。

- Console は公開 API と同じエンドポイント・同じ粒度で呼んでいるとは限らない。**観察できた振る舞いと、内部実装の推測を分ける**
- Cookie やトークンの値はメモに残さない

### `terraform state show`

自分で書いていないのに値が入っている属性は、Console なら「デフォルト値」として表示されている項目である。

## 観点

| 観点 | 問い |
| --- | --- |
| API の粒度 | 1 回の「作成」で、裏で何個の API が呼ばれたか |
| 付随リソース | ウィザードが暗黙に作ったもの(SG、ロール、ロググループ)とその名前・デフォルト値 |
| 非同期と状態遷移 | `pending` / `creating` / `InProgress` を UI はどう見せているか |
| 結果整合性 | 作成直後に一覧に出ない、作ったロールがすぐ使えない、などのラグを UI はどう扱っているか |
| 依存関係と削除 | 消せない理由をどう伝えているか。Console が代わりに順番に消してくれるものは何か |
| デフォルト値 | API では任意なのに UI では選ばせている項目、その逆 |
| グローバルとリージョン | リージョンを切り替えると見えなくなるもの・変わらないもの |
| 段階的開示 | 「簡単作成」と「標準作成」のように、複雑さをどう段階的に見せているか |
